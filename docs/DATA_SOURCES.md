# 채널별 데이터 연결

## 요약

| 채널 | CSV 경로 | API 어댑터 | 상태 |
|---|---|---|---|
| 네이버 검색광고 | `data/raw/naver_sa/` | `naver_sa` | 인증 구현 · **응답 검증 필요** |
| 네이버 검색어 | `data/raw/naver_search_terms/` | — | CSV만 |
| 쿠팡 광고 | `data/raw/coupang_ads/` | `coupang_ads` | 인증 구현 · **응답 검증 필요** |
| 메타/인스타 | `data/raw/meta_ads/` | `meta` | 사용 가능 |
| 구글 | `data/raw/google_ads/` | `google` | 사용 가능 (SDK 필요) |
| 스마트스토어 매출 | `data/raw/sales_smartstore/` | — | CSV만 |
| 쿠팡 매출 | `data/raw/sales_coupang/` | — | CSV만 |
| 자사몰 매출 | `data/raw/sales_own/` | — | CSV만 |
| 카탈로그 | `data/raw/catalog/` | — | 직접 작성 |

**"응답 검증 필요"의 의미:** HMAC 서명 인증은 구현되어 있고 요청은 정상적으로
나간다. 다만 리포트 응답의 JSON 구조가 판매자 계약 유형·광고 상품에 따라
달라져서, 최초 1회 실제 응답을 확인하고 `_parse` 함수를 맞춰야 한다.
검증 전에는 CSV를 쓰는 편이 안전하다.

## CSV 컬럼 인식 방식

컬럼명은 **별칭 목록**으로 매칭한다. 공백·언더스코어·괄호·대소문자를 무시하므로
`광고비`, `광고 비`, `Cost`, `cost` 가 모두 같게 인식된다.

인식에 실패하면 적재 로그에 이렇게 뜬다:

```
[WARN] csv:naver_sa  spend  0행  · keyword_report.csv: 필수 컬럼 미인식 ['cost'] (헤더: [...]) — 이 파일은 건너뜁니다
```

이때 `adops/adapters/csv_source.py`의 `PROFILES`에서 해당 필드의 별칭 목록에
실제 컬럼명을 추가하면 된다. 예:

```python
"cost": ["광고비", "총비용", "비용", "cost", "집행금액"],   # ← 추가
```

인코딩은 `utf-8-sig` → `cp949` → `euc-kr` → `utf-8` 순으로 자동 시도한다.
한국 채널이 내보내는 CSV는 대부분 CP949라 그대로 넣어도 된다.

## 카탈로그 파일 (필수)

이 파일이 없으면 **수익성 분석이 전부 추정치가 된다.** 직접 만들어야 한다.

`data/raw/catalog/catalog.csv`:

```csv
sku,상품명,판매가,원가,카테고리,재고,판매상태
SKU-1001,프리미엄 콜라겐 30포,39000,16000,건강기능식품,240,판매중
SKU-1004,루테인 지아잔틴,29000,12500,건강기능식품,0,판매중
SKU-1006,밀크씨슬 간건강,24000,11000,건강기능식품,90,판매중지
```

- `sku`는 **매출 데이터의 상품코드와 정확히 일치**해야 한다. 채널마다
  코드 체계가 다르면 대표 코드로 통일하거나 채널별 매핑을 따로 둬야 한다.
- `재고 0` 또는 `판매상태=판매중지`인 SKU에 광고비가 나가면 리포트가
  **즉시 중단 대상**으로 잡아낸다. 절감 효과가 가장 확실한 항목이다.
- 재고를 매일 갱신하면 이 진단이 실시간으로 작동한다.

## 채널별 리포트 받는 위치

### 네이버 검색광고
- 보고서 → 다차원 보고서 → **키워드** 차원, 일자별
- 보고서 → **검색어 보고서** ← 반드시 함께 받을 것
- 필요 지표: 노출수, 클릭수, 총비용, 전환수, 전환매출액

### 쿠팡 광고
- 광고 관리 → 보고서 → 일별/키워드별 다운로드
- 상품ID(옵션ID)를 포함시켜야 품절 상품 광고 진단이 작동한다

### 메타 (페이스북/인스타그램)
- 광고 관리자 → 보고서 → 내보내기
- **분류에 '플랫폼'(publisher_platform)을 반드시 포함**해야 페이스북과
  인스타그램이 분리 집계된다. 두 지면의 효율 차이가 커서 합산하면
  판단이 흐려진다.
- 필요 지표: 노출, 링크 클릭, 지출 금액, 구매, 구매 전환값

### 구글 광고
- 보고서 → 사전 정의된 보고서 → 키워드
- 필요 지표: 노출수, 클릭수, 비용, 전환수, 전환가치
- `판매채널` 컬럼을 직접 추가하면 몰별 귀속이 정확해진다

## API 자격증명

`.env` 또는 `hermes config set`으로 넣는다.

### 네이버 검색광고
```
NAVER_AD_API_KEY=...          # 액세스 라이선스
NAVER_AD_SECRET_KEY=...       # 비밀키
NAVER_AD_CUSTOMER_ID=...      # 고객 ID
```
검색광고 관리시스템 → 도구 → API 사용 관리에서 발급.

### 쿠팡
```
COUPANG_ACCESS_KEY=...
COUPANG_SECRET_KEY=...
COUPANG_VENDOR_ID=...
```
쿠팡 윙 → 오픈API 키 발급.

### 메타
```
META_ACCESS_TOKEN=...         # 장기 토큰이어야 함
META_AD_ACCOUNT_ID=...        # act_ 접두어 있어도 없어도 됨
```
**단기 토큰을 쓰면 며칠 만에 만료되어 크론이 조용히 실패한다.**
비즈니스 관리자에서 시스템 사용자 토큰을 발급받는 것이 안정적이다.

### 구글
```
GOOGLE_ADS_CUSTOMER_ID=...
```
추가로 `google-ads.yaml` 또는 `GOOGLE_ADS_*` 환경변수(developer token,
client id/secret, refresh token)가 필요하다. SDK 설치도 필요:

```bash
pip install google-ads
```

## 적재 동작

- **멱등이다.** 같은 날짜·채널 데이터를 여러 번 넣어도 중복되지 않고
  덮어쓴다. 크론이 재시도해도 숫자가 두 배가 되지 않는다.
- **부분 실패를 허용한다.** 한 채널이 실패해도 나머지는 적재되고 리포트는
  발송된다. 대신 리포트 상단에 결손 경고가 뜬다.
- 늦게 올라오는 채널이 있으므로 매일 **최근 3일을 함께 재적재**하는 것을
  권장한다.

```bash
python3 -m adops ingest --from 2026-08-10 --to 2026-08-13
python3 -m adops ingest --source csv --from 2026-08-13 --to 2026-08-13   # 특정 소스만
```
