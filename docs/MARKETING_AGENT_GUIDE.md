## 1. 영상이 주장하는 핵심 — 포렌식 요약

### (1) 채팅 vs 에이전틱, 둘은 다른 도구다

일반 채팅창(클로드 앱, ChatGPT)은 컨텍스트 윈도우가 작아 가벼운 작업
(견적서 1장, 짧은 답변)에 적합하다. 반면 **클로드 코드·코덱스** 같은
에이전틱 도구는 컨텍스트가 훨씬 크고, 여러 단계를 스스로 이어서
수행(리서치 → 기획 → 제작 → 배포)할 수 있다. "마케팅을 자동화하고
싶다"는 목표라면 채팅이 아니라 에이전틱 도구가 맞는 선택이라는 것이
출연자의 첫 번째 주장이다.

### (2) 싱글 에이전트보다 "에이전트팀"이 낫다

한 에이전트가 기획부터 카피, 디자인, 검수까지 혼자 다 하면 품질이
떨어진다. 사람이 촬영·편집·연출로 역할을 나누듯, 에이전트도 **역할별로
분업**시켜 병렬로 일하게 한 뒤 결과를 합치는 편이 품질이 높다. 영상에서
보여준 예시(인스타그램 카드뉴스)는 다음 팀 구성이었다:

- 리서치 에이전트 — 회사/브랜드/주제 조사
- 기획·전략 에이전트 — 콘텐츠 방향·메시지 결정
- 카드 구성·카피라이팅 에이전트 — 실제 문안·구성 작성
- 프로듀서 — 이미지 생성 API 등으로 실물 제작
- 검수 에이전트 — 최종 확인

### (3) 서브에이전트 · 스킬 · 커넥터는 서로 다른 개념

영상에서 든 비유가 명확해서 그대로 정리한다:

| 개념 | 비유 | 역할 |
|---|---|---|
| 서브에이전트 | 정규직 | 맥락을 갖고 "똑똑하게" 일하는 역할 단위 |
| 스킬 | 프리랜서(계약직) | 반복 작업을 빠르게 수행하는 절차 단위 |
| 커넥터(MCP) | 외주 협력사 연결 | 피그마·노션·메타광고 등 외부 서비스 연동 |

이 저장소가 이미 채택하고 있는 구조(`skills/*/SKILL.md`)가 바로
"스킬" 쪽이다. `ad-daily-report`, `ad-monthly-close`가 반복 실행되는
절차형 스킬인 것과 같은 맥락이다.

### (4) 풀 파이프라인은 이미 기술적으로 가능하다

영상 속 사례(리서치 → 소재 제작 → 업로드 자동화 → 측정 대시보드)는
개별 구간이 이미 자동화 가능하다고 소개된다. 다만 **광고 운영 자동
재집행(입찰 최적화 등)은 아직 미흡**하다는 실무적 한계도 함께
언급됐다 — 학습이 초기화되는 문제 등 광고 플랫폼 쪽 제약 때문이다.
그래서 "측정·해석까지는 자동화하되, 집행 판단은 사람이 최종
확인한다"는 경계가 여전히 유효하다.

### (5) 진짜 리스크는 정보 노출이다

- 클라이언트 대외비, API 키, 개인정보를 에이전트에게 통째로 넘기지
  말고 **격리·마스킹**할 것.
- 특히 깃(GitHub 등) 같은 버전관리 도구에 키를 실수로 올리는 사고가
  실제로 있었고, 피해 기업은 대기업과의 거래가 끊기는 수준까지
  갔다고 언급됐다.
- 이 저장소는 이미 `.gitignore`로 `config/config.yaml`(수수료율·원가
  등 대외비)을 커밋 대상에서 제외하고 있다 — 같은 원칙이다.

### (6) 기대치 관리 — 처음부터 완벽을 기대하지 말 것

에이전트는 "맥락 없는 신입"과 같아서 첫 결과물은 대체로 실망스럽다.
반복해서 맥락을 주고 다듬어야 품질이 올라간다는 점을 분명히 짚었다.
한 번 써보고 "별로네" 하고 포기하지 말라는 조언이다.

### (7) 마케터의 기존 역량이 오히려 강점이다

"만들 줄 아는데 팔 줄 모르는" 사람이 다수인 반면, 마케터는 이미
**판매 이해도**를 갖고 있다. 과거에 없었던 역량(개발·자동화)을 AI가
채워주는 지금, 마케터가 제품·실행까지 주도할 수 있는 위치에 있다는
것이 영상의 결론이다.

## 2. 이 저장소에 적용한 방법

이 저장소는 이미 "숫자는 `adops`가 계산하고, 해석은 LLM이 쓴다"는
경계를 갖고 있다(`CLAUDE.md` 참고). 영상의 방법론을 이 경계를 깨지
않는 선에서 결합했다:

```
adops 일일/월간 분석
   │  (조치대기열 · 광고 사각지대 · 소재 피로 신호)
   ▼
content-agent-team 스킬
   │  리서치 → 기획전략 → 카피/소재 초안 → 자체검수
   ▼
out/content-*.md (초안, 사람 승인 대기)
   │  사람이 검토·수정 후
   ▼
실제 채널 업로드 (사람이 최종 실행)
```

- **입력**: `adops`가 이미 찾아낸 상업적 신호(전환 안 되는 상품,
  광고가 안 붙은 잘 팔리는 상품, 소재 피로 등). 새로운 숫자를
  스스로 계산하지 않는다 — 기존 경계를 그대로 지킨다.
- **처리**: 영상의 "에이전트팀" 구조를 하나의 스킬 안에서 역할을
  순서대로 바꿔가며 수행하는 형태로 재현했다 (Hermes 실행 환경은
  클로드 코드의 서브에이전트 병렬 실행을 그대로 쓰지 못하므로,
  같은 분업 원칙을 절차형 스킬로 옮겼다).
- **출력**: 실제 업로드까지 자동화하지 않는다. 카피·소재 초안까지만
  만들고 사람이 최종 승인한다 — 영상에서도 짚은 "집행 자동화는 아직
  리스크가 있다"는 한계를 반영한 설계다.
- **안전장치**: `config/config.yaml`(원가·수수료율 등 대외비)을 콘텐츠
  초안에 인용하지 않는다. 상품명·판매가처럼 대외에 공개돼도 되는
  정보만 쓴다.

자세한 사용법은 [`skills/content-agent-team/SKILL.md`](https://github.com/wonyul01-collab/DRC-/blob/main/skills/content-agent-team/SKILL.md) 참고.

## 3. 바로 시작하는 법 — 영상이 제안한 3가지

1. **유료 플랜으로 체감하기** — 무료 버전과 성능 차이가 크다고
   강조됐다. Hermes에서 이미 쓰고 있는 모델 구독이 이에 해당한다.
2. **튜토리얼을 하나 따라 해보기** — 처음부터 완벽한 결과를 기대하지
   말고, 반복하며 맥락을 쌓는 연습.
3. **작게 시작해서 반복 개선** — `content-agent-team` 스킬을 실제
   상품 하나로 먼저 돌려보고, 결과를 보며 프롬프트·맥락을 다듬는다.
