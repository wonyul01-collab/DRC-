# 월마감 상세 분석

매월 1일, 전월 전체를 결산한다. 일일 리포트가 "어제 뭘 고칠까"라면
이건 **"이번 달 어디에 걸 것인가"**를 정하는 문서다. 그래서 내부 숫자만이
아니라 시장에서 무슨 일이 있었는지를 함께 본다.

## 역할 분담

일일 리포트와 동일하다. **내부 숫자는 전부 `adops`가 계산한다.** 다만
월마감에는 파이프라인이 계산할 수 없는 영역이 하나 있다 — **경쟁사·시장
동향**이다. 이 부분만 웹 조사로 직접 수집한다.

## 언제 쓰나

- 매월 1일 정기 실행 (크론)
- 분기/반기 리뷰 자료가 필요할 때

## 절차 — 1단계: 내부 결산

1. 전월 말일까지 데이터가 다 들어왔는지 확인하고, 누락분을 보충 적재한다:
   ```bash
   cd "$ADOPS_HOME"
   python3 -m adops ingest --from "$(date -d "$(date +%Y-%m-01) -1 month" +%F)" \
                           --to "$(date -d "$(date +%Y-%m-01) -1 day" +%F)"
   python3 -m adops doctor
   ```

2. 월마감 팩 생성:
   ```bash
   python3 -m adops analyze --date "$(date +%F)" --mode monthly --stdout
   ```
   `monthly_close` 블록이 전월 전체를 담는다. `--date`는 오늘(1일)을 주면
   파이프라인이 알아서 직전 달을 대상으로 잡는다.

3. 팩에서 확인할 것:
   - `monthly_close.totals` — 전월 확정 실적
   - `vs_prev_month` / `vs_same_month_last_year` — 전월비·전년동월비
   - `target_achievement` — 목표 달성률 (설정에 목표가 있을 때만)
   - `by_ad_channel` — 채널별 손익분기 대비 성과
   - `sales_bridge` — 매출 증감의 원인 분해
   - `opportunities.budget_reallocation` — 예산 재배분 시뮬레이션

## 절차 — 2단계: 경쟁사·시장 조사

4. `monthly_close.competitors_to_research`의 각 경쟁사에 대해 웹 조사한다.
   `competitor-news-monitor` 스킬이 설치되어 있으면 함께 활용한다.

   **조사 항목:**
   - **신규 제품** — 전월 중 출시된 상품, 우리 주력과 겹치는지
   - **가격 변동** — 주력 상품 판매가, 우리 대비 포지션
   - **프로모션** — 어떤 행사를 했는지, 할인율, 기간, 채널
   - **판매량 신호** — 스마트스토어/쿠팡의 리뷰 수 증감, 랭킹 변화
     (판매량 자체는 공개되지 않으므로 리뷰 증가분을 대리 지표로 쓴다)
   - **콘텐츠·광고** — 새로 도는 광고 소재, 인플루언서 협업

   **출처를 반드시 남긴다.** 확인되지 않은 것은 "확인 불가"라고 쓴다.
   경쟁사 분석은 추측이 섞이기 가장 쉬운 영역이고, 추측에 근거해 예산을
   옮기면 손실이 크다.

5. 우리 상품의 시장 포지션을 확인한다:
   - 주력 키워드의 검색 결과에서 우리 노출 순위
   - 동일 카테고리 상위 노출 상품의 가격대
   - 우리 리뷰 수·평점 추이 (전환율의 선행지표다)

## 절차 — 3단계: 종합 및 발송

6. 코멘터리를 **저장소 안**에 작성한다:

   ```
   $ADOPS_HOME/out/commentary-monthly-<날짜>.html
   ```

   **`/tmp` 등 저장소 밖에 쓰지 마라.** 쓰기가 `HERMES_WRITE_SAFE_ROOT`
   (보통 `/opt/data`) 안으로 제한되어 조용히 거부되고, 해석이 빠진 채로
   리포트가 만들어진다. 작성 후 `ls -l` 로 파일 존재를 확인한다.

   일일 리포트보다 길어도 되지만, 아래 구조를 지킨다:

   ```html
   <div style="font-size:13px;line-height:1.7">
     <p><b>총평:</b> 전월 실적 한 문단 요약</p>

     <h4>1. 무엇이 실적을 움직였나</h4>
     <p>sales_bridge 기준 원인 분해. 트래픽/전환율/객단가 중 무엇이었는지.</p>

     <h4>2. 채널별 판정</h4>
     <p>손익분기 대비 성과. 어느 채널을 줄이고 어디로 옮길지.</p>

     <h4>3. 시장·경쟁사 동향</h4>
     <p>조사 결과. 각 항목에 출처 표기. 확인 불가 항목은 명시.</p>

     <h4>4. 이번 달 실행계획</h4>
     <ol>
       <li><b>[항목]</b> 목표 수치 · 담당 조치 · 점검 시점</li>
     </ol>

     <h4>5. 리스크</h4>
     <p>채널 의존도, 재고, 경쟁 심화 등</p>
   </div>
   ```

7. 리포트 생성 및 발송:
   ```bash
   D="$(date +%F)"
   python3 -m adops report --date "$D" --mode monthly \
     --pack "out/pack-monthly-$D.json" \
     --commentary "out/commentary-monthly-$D.html"
   ```

   출력 마지막 줄이 `코멘터리: 포함됨` 이어야 한다. `없음 (숫자만)` 이면
   6단계의 파일 쓰기가 거부된 것이므로 발송하지 않는다.
   제목: `[월마감] {전월} 광고·매출 결산 · 실매출 {금액} · 전월비 {증감}`

## 함정

- **전월비만 보고 판단하지 마라.** 계절성이 있는 카테고리는 전년동월비가
  더 정확하다. 팩에 둘 다 있다.

- **경쟁사 정보를 단정하지 마라.** "경쟁사A가 점유율을 늘렸다"는 공개
  데이터로 확인 불가능한 경우가 대부분이다. 관찰 가능한 사실(리뷰 수,
  가격, 노출 순위)과 해석을 분리해서 써라.

- **예산 재배분 시뮬레이션을 확정 수치로 인용하지 마라.** 효율 체감 30%를
  가정한 추정치다. "기대 추가매출 N원(추정)"으로 표기한다.

- **실행계획에 측정 가능한 목표를 넣어라.** "효율 개선"은 다음 달에
  달성 여부를 판정할 수 없다. "네이버 검색광고 ROAS를 손익분기 대비
  1.2배로" 같은 형태여야 한다.

- **전월 데이터가 불완전하면 마감하지 마라.** `doctor`에서 결손이 확인되면
  먼저 사용자에게 알리고 보충 후 진행한다. 잘못된 마감 수치는 이후 모든
  비교의 기준이 되어 오류가 누적된다.

## 검증

- [ ] `doctor` 결과 전월 구간에 데이터 결손이 없다
- [ ] 전월비와 전년동월비를 모두 인용했다
- [ ] 경쟁사 항목마다 출처가 있거나 "확인 불가"로 표기했다
- [ ] 추정치에 '(추정)' 표기가 있다
- [ ] 실행계획 각 항목에 측정 가능한 목표와 점검 시점이 있다
- [ ] 전월 일일 리포트에서 제기했던 조치의 이행 결과를 언급했다
