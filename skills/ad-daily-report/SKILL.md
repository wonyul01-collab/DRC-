# 일일 광고 효율 분석

스마트스토어·쿠팡·자사몰의 매출과, 네이버 검색광고·쿠팡광고·메타·인스타·구글의
광고비를 대조해 **어제 하루 무엇이 돈을 벌었고 무엇이 돈을 태웠는지**를
판정하고, 오늘 손댈 것을 금액 임팩트 순으로 제시한다.

## 역할 분담 — 반드시 지킬 것

**숫자는 전부 `adops` 파이프라인이 계산한다. 너는 계산하지 않는다.**

광고비, 매출, ROAS, 손익분기 ROAS, 공헌이익, 절감액 추정 — 이 모든 것은
`analyze` 단계에서 결정론적으로 산출되어 JSON 팩에 들어 있다. 너는 그 JSON을
읽고 **해석과 개선방안만** 쓴다.

숫자를 다시 더하거나, 비율을 새로 구하거나, "대략 ~정도"라고 어림하지 마라.
매일 조금씩 틀린 숫자가 나가는 리포트는 신뢰를 잃고 아무도 안 읽게 된다.
팩에 없는 수치가 필요하면, 지어내지 말고 "해당 지표는 현재 산출되지 않음"이라고 써라.

## 언제 쓰나

- 매일 아침 정기 발송 (크론)
- 특정 날짜를 다시 분석해야 할 때 (`--date` 지정)

**쓰지 않는 경우:** 월마감 상세 분석은 `ad-monthly-close`를 쓴다.

## 절차 — 최초 1회 설정

1. 저장소 위치와 설정 확인:
   ```bash
   cd "$ADOPS_HOME" && python3 -m adops doctor
   ```
   `채널 수수료율`과 `손익분기 ROAS`가 실제 사업 구조와 맞는지 확인한다.
   **이 값이 틀리면 리포트의 모든 판정이 무의미하다.** 어긋나면 사용자에게
   알리고 `config/config.yaml`을 고치도록 요청한 뒤 중단한다.

2. 데이터 소스 상태를 확인한다. `[X]`로 표시된 소스가 있으면 그 채널은
   수치가 빠진 채로 리포트가 나간다는 뜻이다. 첫 실행 시 사용자에게 알린다.

## 절차 — 매일 실행

3. **적재.** 전날 데이터를 가져온다. 어제 파일이 늦게 올라오는 채널이 있으므로
   최근 3일을 함께 다시 넣는다(멱등이라 중복되지 않는다):
   ```bash
   cd "$ADOPS_HOME"
   python3 -m adops ingest --from "$(date -d '3 days ago' +%F)" --to "$(date -d yesterday +%F)"
   ```

4. **분석 팩 생성.**
   ```bash
   python3 -m adops analyze --date "$(date -d yesterday +%F)" --stdout
   ```
   표준출력의 JSON을 읽는다. 파일 경로도 함께 출력된다.

5. **팩을 읽고 판단한다.** 반드시 이 순서로 본다:

   a. `data_quality.gaps` — 비어 있지 않으면 **가장 먼저** 다룬다. 결손이 있는데
      "매출이 급감했습니다"라고 쓰면 오진이다. 결손 채널을 명시하고, 해당 수치는
      과소계상되었음을 경고한 뒤 나머지를 분석한다.

   b. `action_queue` 상위 5~7건 — 오늘 조치할 것. 이게 리포트의 핵심이다.

   c. `today.by_store_channel` 의 `verdict` — 채널별 판정.
      `즉시축소`/`전환없음`이 있으면 이유를 파고든다.

   d. `comparison.vs_last_week_same_dow` — 전주 동요일 대비. 전일 대비는 요일
      효과 때문에 오해를 부르므로 본문에서는 동요일 비교를 우선 인용한다.

   e. `opportunities.sales_bridge` — 매출이 빠졌다면 원인이 트래픽인지 전환율인지
      객단가인지. **처방이 완전히 다르므로 반드시 짚는다.**

   f. `trends.monthly` 와 `trends.keyword_monthly` — 올해 흐름. 오늘 숫자가
      추세 안에서 정상 범위인지 판단하는 근거.

6. **코멘터리 작성.** 아래 형식의 HTML 조각을 **저장소 안**에 쓴다:

   ```
   $ADOPS_HOME/out/commentary-daily-<날짜>.html
   ```

   **`/tmp` 등 저장소 밖에 쓰지 마라.** 쓰기가 `HERMES_WRITE_SAFE_ROOT`
   (보통 `/opt/data`) 안으로 제한되어 있어 조용히 거부된다. 거부되면
   해석이 빠진 채로 리포트가 만들어진다.

   `<style>`이나 `<script>`는 쓰지 마라(메일에서 제거된다). 인라인 스타일만.

   ```html
   <div style="font-size:13px;line-height:1.7">
     <p><b>한 줄 요약:</b> …</p>
     <p><b>오늘 가장 중요한 것:</b> …</p>
     <ol>
       <li><b>[제목]</b> 관찰 → 원인 추정 → 구체적 조치 → 기대 효과</li>
     </ol>
     <p><b>지켜볼 것:</b> …</p>
   </div>
   ```

   작성 원칙:
   - **원인 추정과 사실을 구분해서 쓴다.** "전환율이 8% 떨어졌다"는 사실,
     "상세페이지 이슈로 보인다"는 추정이다. 추정에는 '~로 추정된다'를 붙인다.
   - 조치는 실행 가능한 단위로. "효율을 개선한다"가 아니라 "키워드 X 입찰가를
     Y원으로 인하"처럼.
   - 3~5건이면 충분하다. 길면 안 읽는다.

7. **리포트 생성 및 발송.**
   ```bash
   D="$(date -d yesterday +%F)"
   python3 -m adops report --date "$D" \
     --pack "out/pack-daily-$D.json" \
     --commentary "out/commentary-daily-$D.html"
   ```

   출력의 마지막 줄에 `코멘터리: 포함됨` 이 찍혀야 한다. `없음 (숫자만)`
   이거나 명령이 실패하면 6단계의 파일 쓰기가 거부된 것이다. 그 상태로
   발송하지 마라.
   생성된 HTML 파일을 본문으로 하여 메일 발송한다. 제목:
   `[광고 리포트] {날짜} · 실매출 {금액} · 공헌이익 {금액}`

   수신처는 `EMAIL_HOME_ADDRESS` 및 설정된 추가 수신자 전원.

## 함정

- **채널 전환매출을 다 더해서 총매출로 쓰지 마라.** 각 채널이 같은 주문을
  중복 귀속하므로 항상 부풀려진다. 팩의 `attribution_gap`이 그 괴리율이다.
  수익성 판단은 언제나 `realized_sales`(실매출) 기준이다.

- **ROAS 300%를 일률적 목표로 쓰지 마라.** 채널별 수수료와 상품별 마진이
  달라서 손익분기점이 다르다. 팩의 `bep_roas`가 그 채널의 진짜 기준선이다.

- **표본이 적은 키워드를 근거로 결론 내지 마라.** 파이프라인이 이미
  `min_clicks`/`min_cost` 미만은 판정에서 제외했다. 그 아래 것을 굳이
  끌어와 언급하지 마라.

- **전일 대비 급락에 과민 반응하지 마라.** 월요일·명절·프로모션 종료일은
  구조적으로 낮다. 전주 동요일 비교를 먼저 본다.

- **적재가 실패해도 리포트는 발송한다.** 단, 결손 경고를 최상단에 넣는다.
  침묵하는 것이 잘못된 숫자를 보내는 것보다 낫다는 말은 여기선 틀렸다 —
  아무것도 안 오면 사용자는 문제를 모른다.

- **파일을 썼다고 스스로 단정하지 마라.** 쓰기 경로가 샌드박스 밖이면
  거부되는데, 도구 호출 자체는 성공한 것처럼 보일 수 있다. 코멘터리를
  작성한 뒤에는 반드시 파일이 실제로 존재하는지 확인하고 넘어간다:
  ```bash
  ls -l "out/commentary-daily-$D.html"
  ```

## 검증

발송 전 다음을 확인한다:

- [ ] `data_quality.gaps`를 확인했고, 결손이 있으면 리포트 상단에 경고가 있다
- [ ] 코멘터리 파일이 **실제로 존재한다** (`ls -l` 로 확인, 크기 0 아님)
- [ ] `report` 출력 마지막 줄이 `코멘터리: 포함됨` 이다
- [ ] 코멘터리의 모든 숫자가 팩에서 그대로 인용된 것이다 (직접 계산한 것 없음)
- [ ] 조치 항목이 각각 "무엇을, 얼마나, 언제까지"를 담고 있다
- [ ] 추정과 사실이 문장에서 구분되어 있다
- [ ] HTML에 `<style>`, `<script>`, 외부 이미지 링크가 없다
- [ ] 제목에 날짜와 핵심 수치가 들어 있다
