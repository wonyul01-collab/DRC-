# 광고 효율 분석 자동화 (Hermes)

스마트스토어·쿠팡·자사몰의 매출과 네이버 검색광고·쿠팡광고·메타·인스타·구글의
광고비를 대조해, **매일 아침 개선방안이 담긴 리포트를 메일로 보낸다.**
매월 1일에는 전월 마감 상세 분석을 별도로 보낸다.

---

## 설계 원칙

**숫자는 Python이 계산하고, 해석과 개선방안만 LLM이 쓴다.**

광고비·ROAS·손익분기점·공헌이익·절감 추정액은 전부 `adops` 파이프라인이
결정론적으로 산출해 JSON 팩에 담는다. Hermes 스킬은 그 팩을 읽고 해석만
작성한다. LLM에게 숫자를 계산시키면 매일 조금씩 틀린 리포트가 나가고,
그런 리포트는 곧 아무도 읽지 않게 된다.

```
채널 CSV / API
      │
      ▼
  [어댑터]  ──▶ 정규화 스키마 (spend / sales / search_terms / catalog)
      │
      ▼
  [SQLite]  멱등 적재 — 재시도해도 중복되지 않음
      │
      ▼
  [분석]    지표 · 키워드 진단 · 트렌드 · 반등 레버
      │
      ▼
  분석 팩 (JSON)  ──▶ [Hermes 스킬] 해석 · 개선방안 작성
      │                      │
      └──────────┬───────────┘
                 ▼
          HTML 리포트 ──▶ 메일 발송
```

## 무엇을 분석하는가

### 매일
- 판매채널별 매출·광고비·**공헌이익**, 채널 판정(증액검토/유지/개선필요/즉시축소)
- 광고채널별 ROAS와 **손익분기 ROAS 대비** 성과
- 전주 동요일 대비 증감 (요일 효과 제거)
- **불필요 키워드 도출** — 전환 0 지출, 손익분기 미달, 고CPC·저전환, 브랜드 잠식
- **제외키워드 후보** (검색어 리포트 기반)
- **키워드 승격 후보** — 성과 좋은데 미등록된 검색어
- 올해 월별 매출·광고비 추이, 핵심 키워드별 월별 매출 추이
- **금액 임팩트 순 조치 대기열** — 오늘 뭘 먼저 손댈지

### 매월 1일
- 전월 확정 손익, 전월비·전년동월비, 목표 달성률
- 매출 증감 요인분해
- **경쟁사 동향** — 신규 제품, 가격, 프로모션, 리뷰 추이 (웹 조사)
- 이번 달 실행계획

### 추가로 넣은 분석 (매출 반등 레버)

낭비 키워드만 끄면 비용과 함께 매출도 줄어든다. 가라앉은 매출을 끌어올리려면
"어디에 더 쓸 것인가"가 함께 있어야 해서 다음을 추가했다.

| 분석 | 무엇을 답하는가 |
|---|---|
| **품절·판매중지 상품 광고비** | 매출 손실 0으로 즉시 절감 가능한 금액 |
| **매출 증감 요인분해** | 트래픽/전환율/객단가 중 무엇이 원인인가 — 처방이 완전히 다름 |
| **예산 재배분 시뮬레이션** | 적자 채널에서 얼마를 빼서 어디로 옮길 것인가 |
| **광고 사각지대** | 잘 팔리는데 광고가 안 붙은 상품 |
| **CAC 회수 주문수** | 신규 고객 획득이 첫 주문으로 회수되는가 |
| **요일별 효율** | 요일 입찰 조정의 근거 |
| **키워드 승격 후보** | 광범위 매칭에 묻혀 있는 고효율 검색어 |

## 빠른 시작

```bash
# 1. 설정
cp config/config.example.yaml config/config.yaml
$EDITOR config/config.yaml        # 채널 수수료율을 실제 정산 기준으로

# 2. 샘플 데이터로 동작 확인
python3 tools/make_sample_data.py
python3 -m adops ingest --from 2026-01-01 --to 2026-08-13
python3 -m adops doctor
python3 -m adops report --date 2026-08-13
# → out/report-daily-2026-08-13.html
```

의존성 설치가 필요 없다. 표준 라이브러리만 쓴다.
(구글 광고 API를 쓸 때만 `pip install google-ads`)

실제 데이터 연결은 [docs/SETUP.md](docs/SETUP.md),
Hermes 스킬·크론·메일 설정도 같은 문서에 있다.

## 명령

```bash
python3 -m adops doctor                          # 설정·데이터 상태 점검
python3 -m adops ingest --from DATE --to DATE    # 적재 (멱등)
python3 -m adops analyze --date DATE             # 분석 팩(JSON) 생성
python3 -m adops report  --date DATE             # HTML 리포트 생성
python3 -m adops report  --date DATE --mode monthly
```

크론을 걸기 전에 **반드시 `doctor`를 먼저 돌려라.** 채널 수수료율이 틀리면
손익분기 ROAS가 통째로 틀어지고, 리포트의 모든 판정이 무의미해진다.

---

## 왜 이렇게 계산하는가

리포트에서 가장 중요한 숫자는 **손익분기 ROAS**다.

```
공헌이익률   = 매출총이익률 − 채널수수료율
손익분기 ROAS = 1 ÷ 공헌이익률
```

스마트스토어(수수료 5.85%, 마진 45%)는 손익분기가 **255%**,
쿠팡(수수료 10.8%)은 **292%**다. "ROAS 300% 나왔으니 잘했다"가 왜
위험한지가 여기 있다 — 쿠팡에서 300%는 거의 본전이다.

이런 판단 근거는 전부 [docs/METRICS.md](docs/METRICS.md)에 정리해 두었다.
어트리뷰션 괴리, 표본 하한, 요인분해 수식, 예산 재배분 가정까지 포함한다.

## 알려진 제약

- **네이버·쿠팡 API 어댑터는 최초 1회 응답 검증이 필요하다.** HMAC 서명 인증은
  구현되어 있으나, 리포트 응답 스키마가 판매자 계약 유형에 따라 달라진다.
  검증 전에는 CSV 어댑터를 쓰는 것이 안전하다. 메타·구글은 그대로 사용 가능하다.
- 카탈로그에 원가가 없으면 수익성 분석이 추정치가 된다. `doctor`가 미등록
  SKU 수를 경고한다.
- 경쟁사 판매량은 공개 데이터로 확인 불가능하다. 리뷰 수 증감을 대리 지표로 쓴다.
