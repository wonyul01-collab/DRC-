# 실데이터 준비 서식

리포트가 실제 값어치를 내려면 아래 셋이 필요하다. 기술 설정과 무관하게
사람이 모아야 하는 것들이라, 대개 여기가 병목이 된다.

---

## 1. 채널별 실효 수수료율 — 가장 중요

`config/config.json` 의 `channel_fees` 를 **정산서 기준 실제 수수료율**로
바꾼다. 지금 들어 있는 값은 예시다.

```json
"channel_fees": {
  "smartstore": 0.0585,
  "coupang": 0.108,
  "own": 0.033
}
```

- 플랫폼 판매수수료 **+ 결제수수료**를 합산한 값
- **쿠팡은 카테고리마다 다르다.** 주력 카테고리 기준으로 확인할 것
- 정산서에서 `실제 공제액 ÷ 판매금액` 으로 역산하는 것이 가장 정확하다

이 값이 손익분기 ROAS의 분모다. 틀리면 "어느 키워드를 끌지, 어느 채널을
줄일지" 판정이 전부 어긋난다. 리포트에서 단 하나만 정확해야 한다면 이것이다.

## 2. SKU 원가 — `catalog.csv`

같은 폴더의 `catalog.csv` 를 복사해 실제 상품으로 채운 뒤
`data/raw/catalog/catalog.csv` 로 넣는다.

### 엑셀에서 한글이 깨져 보인다면

한국어 윈도우 엑셀은 `.csv` 를 CP949 로 여는 것이 기본이라, UTF-8 파일의
한글이 `?맬?以?` 처럼 깨져 보인다. **파일이 손상된 것이 아니라 엑셀이
잘못 읽는 것이다.** 메모장이나 GitHub 에서 열면 멀쩡하다.

이 서식에는 BOM 을 붙여두어 엑셀이 UTF-8 로 인식한다. 그래도 깨지면
파일을 직접 열지 말고 엑셀에서 불러온다:

> 데이터 → 텍스트/CSV 가져오기 → 파일 선택 → **원본 파일: 65001 : 유니코드(UTF-8)**

**저장할 때는** `CSV UTF-8(쉼표로 분리)` 과 `CSV(쉼표로 분리)` 중 아무거나
써도 된다. 적재 시 UTF-8·CP949·EUC-KR 을 자동 판별한다.

| 컬럼 | 설명 |
|---|---|
| `sku` | 우리가 정하는 **통합 코드**. 채널 코드와 달라도 된다 (아래 3번 참고) |
| `상품명` | 리포트 표시용 |
| `판매가` | 정상 판매가 |
| `원가` | 매입원가. 이게 없으면 수익성 분석이 전부 추정치가 된다 |
| `카테고리` | 선택 |
| `재고` | `0` 이면 품절 광고 진단이 작동한다 |
| `판매상태` | `판매중` / `판매중지` |

`재고` 와 `판매상태` 를 주기적으로 갱신하면, **품절·중지 상품에 나가는
광고비**를 매일 자동으로 잡아낸다. 매출 손실 없이 즉시 줄일 수 있는
항목이라 절감 효과가 가장 확실하다.

## 3. 채널별 상품코드 매핑 — `sku_map.csv`

**같은 상품인데 채널마다 코드가 다르다.** 스마트스토어는 상품번호,
쿠팡은 옵션ID, 자사몰은 자체 코드를 쓴다. 카탈로그의 `sku` 하나로는
한 채널만 맞고 나머지는 원가가 대조되지 않는다.

그러면 그 채널 매출이 전부 기본 마진율로 추정되고, **손익분기 ROAS 가
통째로 어긋난다.** 실제로 매핑 하나로 이만큼 달라진다:

```
매핑 전   smartstore  매출총이익률 45.0%(추정)   손익분기 ROAS 255%
매핑 후   smartstore  매출총이익률 59.0%(실제)   손익분기 ROAS 188%
```

ROAS 200% 인 키워드가 매핑 전에는 '적자, 중단', 매핑 후에는 '흑자, 유지'
로 정반대 판정이 난다. 매핑 없이 돌리면 멀쩡한 키워드를 끄게 된다.

### 방법 A — 상품 목록을 올리면 자동으로 매칭한다 (권장)

각 채널 관리자에서 **상품 목록**을 내려받아 아래 폴더에 넣는다.

```
data/raw/products_smartstore/    스마트스토어 → 상품관리 → 상품 조회/수정 → 엑셀 다운
data/raw/products_coupang/       쿠팡 윙 → 상품관리 → 상품 조회/수정 → 엑셀 다운
data/raw/products_own/           자사몰 상품 목록
```

필요한 컬럼은 **상품코드·상품명·판매가** 셋뿐이다. 나머지 컬럼이 많아도
무시하므로 받은 파일을 그대로 넣으면 된다.

```bash
python3 -m adops ingest --from 2026-05-21 --to 2026-08-20
python3 -m adops automap
```

상품명을 대조해 채널 간 같은 상품을 묶고 통합 SKU 를 붙인다.

```csv
채널,채널상품코드,통합SKU,비고
smartstore,1234567890,SKU-1001,[무료배송] 프리미엄 콜라겐 30포 (정품) [카탈로그 상품명 유사 100%]
coupang,87654321,SKU-1001,프리미엄 콜라겐 30포 [카탈로그 상품명 유사 100%]
own,P-1001,SKU-1001,프리미엄콜라겐30포 [카탈로그 상품명 유사 100%]
coupang,87654322,SKU-1002,[로켓배송] 프리미엄 콜라겐 60포 [신규 부여]
```

판촉 문구(`[무료배송]`, `(정품)`, `로켓배송`)는 무시하고, **수량·용량이
다르면 묶지 않는다.** `콜라겐 30포` 와 `콜라겐 60포` 는 이름이 90% 넘게
같지만 다른 상품이고, 잘못 묶으면 원가가 통째로 틀어지기 때문이다.

카탈로그에 이미 있는 상품이면 **그 SKU 를 재사용**한다. 새 번호를 붙이면
이미 입력해 둔 원가가 연결되지 않고 버려진다.

**결과를 그대로 믿지 말고 한 번 훑어보라.** 확신이 낮은 짝은 자동 확정하지
않고 `_검토필요.csv` 로 따로 빠지며, 한 채널에만 있는 상품은 목록 끝에
표시된다. 확인한 파일을 `data/raw/sku_map/` 에 넣고 다시 적재하면 적용된다.

### 방법 B — 서식만 받아 직접 채운다

상품 목록을 받기 어렵거나 자동 매칭 결과를 손보고 싶을 때. 매출·광고
데이터를 먼저 적재한 뒤:

```bash
python3 -m adops skumap
```

아직 원가가 대조되지 않는 코드만 **매출 큰 순서로** 뽑아 `sku_map_작성용.csv`
를 만든다. 상품명과 매출액이 비고에 붙어 있어 어떤 상품인지 바로 안다.

```csv
채널,채널상품코드,통합SKU,비고
smartstore,1234567890,,"프리미엄 콜라겐 30포 (매출 390,000원)"
coupang,87654321,,"콜라겐 30포 (매출 195,000원)"
own,P-1002,,"비타민D (매출 57,000원)"
```

**`통합SKU` 한 칸만 채우면 된다.** 같은 상품이면 같은 값을 적는다:

```csv
smartstore,1234567890,SKU-1001,...
coupang,87654321,SKU-1001,...      ← 같은 상품이므로 같은 SKU
own,P-1002,SKU-1002,...
```

채운 파일을 `data/raw/sku_map/` 에 넣고 다시 적재하면 적용된다.
`통합SKU` 는 `catalog.csv` 의 `sku` 와 일치해야 한다.

- 채널 구분 없이 같은 코드를 쓰는 상품은 채널 칸에 `*` 를 적는다.
- 채널을 지정한 매핑이 `*` 매핑보다 우선한다.
- 매핑은 **조회 시점에 적용**된다. 나중에 추가해도 과거 데이터에 바로
  반영되므로 다시 내려받을 필요가 없다.

매출이 큰 상품부터 채우면 된다. 전부 채우지 않아도 채운 만큼 정확해지고,
`doctor` 가 남은 미매핑 코드와 그 매출 규모를 계속 알려준다.

## 4. 광고·매출 CSV

각 채널 관리자에서 받아 `data/raw/<폴더>/` 에 넣는다. 폴더 구조와
받는 위치는 [../docs/DATA_SOURCES.md](../docs/DATA_SOURCES.md) 참고.

**최근 3개월치를 먼저 넣으면** 월별 추이와 키워드 추세가 첫날부터 나온다.
하루치만 넣으면 트렌드 분석이 비어 있는 리포트가 된다.

### 빠뜨리기 쉬운 것

**네이버 검색어 보고서** (`data/raw/naver_search_terms/`) 를 꼭 함께
받을 것. 제외키워드 후보와 승격 후보는 **전적으로 이 데이터에서만** 나온다.
키워드별 성과 보고서만으로는 산출이 불가능하고, 실무 절감 효과는 이쪽이
더 크다.

**메타 리포트의 '플랫폼' 분류**도 포함시킬 것. 페이스북과 인스타그램은
효율 차이가 커서 합산하면 판단이 흐려진다.

## 순서 정리

```bash
# 1) 받은 파일을 폴더로 분류
python3 -m adops classify --move

# 2) 적재
python3 -m adops ingest --from 2026-05-21 --to 2026-08-20

# 3) 매핑이 필요한 코드 추출 → 통합SKU 칸 채우기
python3 -m adops skumap
#    채운 파일을 data/raw/sku_map/ 에 넣고

# 4) 다시 적재 후 확인
python3 -m adops ingest --from 2026-05-21 --to 2026-08-20
python3 -m adops doctor
```

`doctor` 에서 확인할 것:

- `손익분기 ROAS` 가 상식적인 값인지, 그리고 **매출총이익률이 추정값(기본
  45%)이 아니라 실제 원가에서 나온 값인지**
- `SKU 매핑 등록` 건수와 남은 미매핑 코드
- 각 표의 행 수와 날짜 범위가 기대와 맞는지
