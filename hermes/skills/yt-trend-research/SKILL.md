# 유튜브 소재 리서치

채널 브리프를 읽고, 웹에서 실제 수요를 확인한 뒤, **바로 대본으로 넘길 수 있는 기획안**을 만든다.
"아이디어 나열"로 끝내지 말 것. 각 기획안은 `yt-shorts-factory` 가 그대로 받아 쓸 수 있어야 한다.

## 입력

1. `skills.config.yt-shorts-factory.brief_path` 의 채널 브리프를 읽는다.
   없으면 사용자에게 니치·타깃·판매 상품을 물어보고 브리프를 먼저 만든다.
2. 기존 성과 데이터가 있으면 참고한다:
   `python ~/.hermes/workspace/youtube/scripts/youtube_analytics.py videos --days 28`

## 절차

1. **수요 확인** — 웹 검색으로 해당 니치에서 지금 사람들이 실제로 검색·질문하는 것을 찾는다.
   커뮤니티 질문글, 최근 뜬 영상 제목, 계절성 이슈를 본다.
   추측으로 소재를 만들지 말고 근거 URL을 남긴다.
2. **경쟁 밀도 판단** — 같은 소재로 이미 대형 채널이 반복 제작 중이면 각도를 비튼다.
   (예: "엑셀 단축키" → "면접에서 엑셀 실력 들통나는 순간 3가지")
3. **목적 연결** — 브리프의 `stage` 에 따라 기준이 다르다.
   - `practice`: 벤치마크 채널의 후킹 공식을 연습하기 좋은 소재인가를 본다.
     상품은 아직 없어도 된다.
   - `growth`: 같은 시청자를 반복해서 데려올 소재인가를 본다.
   - `monetize`: 브리프의 판매 상품과 이어지지 않는 소재는 버린다.
4. **기획안 작성** — 아래 형식으로 요청 편수만큼 만든다.

## 출력 형식

`{output_dir}/plans/YYYY-MM-DD-plans.yaml` 에 저장하고, 요약은 대화로 보고한다.

```yaml
- id: 2026-08-13-01
  hook: "첫 2초에 나올 한 문장"          # 이게 약하면 나머지는 의미 없다
  title: "제목 (한글 40자 이내 권장)"
  angle: "왜 이 각도인가 — 한 줄"
  target_viewer: "누가 이걸 보고 멈추는가"
  beats:                                  # 대본의 뼈대. 3~5개.
    - "0-2초: 문제 제기"
    - "2-8초: 근거 하나"
    - "8-15초: 해법"
    - "15-20초: 다음 행동 유도"
  visual_direction: "영상 톤/장면 요약 — Higgsfield 프롬프트의 재료"
  hook_type: "reference-style.yaml 의 hooking.types 중 어느 것을 쓰는가"
  cta: "마지막 한 문장. 판매 단계 전에는 구독/다음 편 유도로 충분하다."
  product_link: "판매 단계에서만. 아직 없으면 비워둔다."
  evidence:
    - "https://... (이 수요가 실재한다는 근거)"
  risk: "저작권·초상권·사실관계 위험이 있으면 여기 적는다. 없으면 none"
```

## 하지 말 것

- 실존 인물·브랜드를 사칭하거나, 있지도 않은 사건을 사실처럼 보이게 하는 소재는 만들지 않는다.
- 의료·금융·법률 조언은 단정형으로 쓰지 않는다. 채널 수익화가 통째로 날아갈 수 있다.
- 같은 템플릿에 단어만 바꾼 기획안을 대량으로 찍어내지 않는다.
  YouTube 는 이런 "대량 양산·비진정성 콘텐츠"를 수익화에서 제외한다.
  기획안 하나하나가 서로 다른 관점을 가져야 한다.
