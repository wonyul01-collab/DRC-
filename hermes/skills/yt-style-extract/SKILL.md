# 레퍼런스 스타일 추출

사람이 읽는 분석 노트를 **제작 파이프라인이 읽는 설정 파일**로 바꾼다.
결과물은 `~/.hermes/workspace/youtube/reference-style.yaml` 하나다.

## 입력으로 받는 것

아래 중 무엇이든. 여러 개면 합쳐서 본다.

- 옵시디언 보관소 경로 (`00_Templates/`, `10_Methodology/`, `20_Scripts_Database/` 구조)
- NotebookLM 에서 내보낸 마크다운 (`obsidian-shorts-vault-starter.md` 같은)
- 대본 텍스트 모음
- 영상 URL 목록 (이 경우 제목·설명·댓글만 볼 수 있다는 한계를 먼저 알린다)

경로를 못 받았으면 **추측하지 말고 물어본다.** 어디에 있는지 한 줄이면 된다.

## 절차

1. **훑기** — 자료 전체를 먼저 읽고, 반복되는 패턴이 무엇인지 목록으로 뽑는다.
   한두 편에만 나온 건 패턴이 아니다. 최소 3편 이상에서 반복돼야 스타일로 인정한다.

2. **분류** — 뽑은 패턴을 `reference-style.yaml` 의 6개 섹션에 배치한다.

   | 섹션 | 여기 들어갈 것 |
   |---|---|
   | `hooking` | 첫 2~3초 문장 틀, 오프닝 자막 글자수·타이밍, 이탈 방지 장치 |
   | `structure` | 총 길이, 시간대별 역할, 평균 컷 길이, 엔딩 시그니처 |
   | `subtitle` | 폰트 크기·색·외곽선·위치, 한 번에 띄우는 글자수 |
   | `voice` | 화자 성별·속도·톤, 무음 구간 사용 여부 |
   | `visual` | 색감, 카메라, 피사체 종류, BGM |
   | `do_not_copy` | 따라 하면 안 되는 것 |

3. **수치화** — "빠른 편집" 같은 형용사는 쓰지 않는다.
   `avg_shot_seconds: 1.4` 처럼 숫자로 바꾼다. 자료에 숫자가 없으면 대본 길이와
   영상 길이로 역산하거나, 모르면 `null` 로 두고 무엇이 비었는지 보고한다.
   **모르는 값을 그럴듯하게 채우지 않는다.** 그 값이 그대로 영상에 반영된다.

4. **자막 설정은 실제로 렌더링되는 값**임을 잊지 않는다.
   `font_family` 는 시스템에 설치된 폰트명이어야 한다. 확인:
   ```bash
   fc-list :lang=ko family | sort -u
   ```
   한글 폰트가 없으면 사용자에게 설치를 요청한다 (예: Noto Sans KR, 프리텐다드).

5. **저장** — `~/.hermes/workspace/youtube/reference-style.yaml`.
   기존 파일이 있으면 덮어쓰기 전에 `.bak` 로 백업한다.

6. **검증** — 다음을 확인하고 보고한다.
   - YAML 파싱이 되는가
   - `hooking.types` 가 2개 이상 있는가
   - `subtitle.font_family` 가 실제 설치된 폰트인가
   - 비어 있는 필드가 무엇인가 (목록으로)

## 출력 보고

대화로는 짧게. 파일이 결과물이다.

1. 분석한 자료 편수와 출처
2. 발견한 후킹 유형 목록 (빈도 순)
3. 이 채널의 문법을 한 문단으로 요약
4. **못 채운 필드 목록** — 여기가 다음에 보완할 곳이다

## 선 긋기 — 중요

이 스킬은 **포맷을 배우는 것이지 콘텐츠를 복제하는 것이 아니다.**

- 대본 문장을 `reference-style.yaml` 에 그대로 옮기지 않는다. 문장 *틀* 만 가져온다.
  ("A vs B, 이기는 쪽은?" 은 틀이고, "삼성 vs 애플, 이기는 쪽은?" 은 남의 대본이다.)
- 원본 영상 클립, 로고, 고유 캐릭터, 시그니처 사운드는 가져오지 않는다.
- 채널명이 헷갈릴 만큼 비슷하면 사용자에게 다른 이름을 권한다.

이유는 두 가지다. 저작권 문제이기도 하고, YouTube가 **재사용·복제 콘텐츠**를
수익화에서 제외하기 때문이다. 포맷은 보호 대상이 아니지만 표현은 보호 대상이다.
성공한 채널의 *문법*을 배워서 *내 소재*에 적용하는 것이 목표다.
