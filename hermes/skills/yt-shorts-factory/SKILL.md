# 쇼츠 제작 파이프라인

기획안 하나 → 대본 → 영상 → 비공개 업로드까지 끝낸다.
**공개(public)는 절대 자동으로 하지 않는다.** 사람이 검수한 뒤 직접 공개한다.

## 전제

- Higgsfield MCP 가 연결되어 있어야 한다. 툴이 안 보이면 `hermes mcp login higgsfield` 를 먼저 안내한다.
- Higgsfield 는 유료 크레딧을 쓴다. 생성 1회는 곧 돈이다. 실패를 줄이는 쪽으로 움직인다.

## 설정값 (skills.config.yt-shorts-factory)

| 키 | 의미 |
|---|---|
| `brief_path` | 채널 브리프 경로 |
| `output_dir` | 생성물 저장 위치 |
| `daily_video_cap` | 하루 최대 생성 편수 (크레딧 폭주 방지) |
| `default_privacy` | 업로드 공개 범위 (기본 `private`) |

## 절차

### 1. 사전 점검 — 크레딧을 쓰기 전에 반드시

- 오늘 이미 만든 편수를 `{output_dir}/log.jsonl` 에서 센다.
  `daily_video_cap` 에 도달했으면 **생성하지 말고 중단**하고 사용자에게 보고한다.
- 기획안의 `risk` 가 `none` 이 아니면 생성 전에 사용자에게 확인받는다.

### 2. 대본 작성

기획안의 `beats` 를 실제 낭독 대본으로 옮긴다.

- 쇼츠는 **15~40초**, 한국어 기준 초당 4~5음절로 계산해 분량을 맞춘다.
- 첫 문장이 전부다. 훅이 밋밋하면 대본을 다시 쓴다.
- 마지막에 CTA 한 문장. "구독" 만 말하지 말고 브리프의 상품/리드마그넷으로 보낸다.
- `{output_dir}/scripts/{id}.md` 에 저장한다.

### 3. 영상 생성 (Higgsfield MCP)

- 먼저 사용 가능한 툴과 모델을 확인한다. 툴 이름을 추측해서 호출하지 않는다.
- 세로 영상으로 만든다: 종횡비 **9:16**.
- 프롬프트에는 기획안의 `visual_direction` 을 구체적인 장면 묘사로 풀어 쓴다.
  카메라 움직임, 피사체, 조명, 분위기를 명시한다.
- 컷이 여러 개면 **한 컷씩 순차 생성**한다. 병렬로 돌리지 않는다 (크레딧·레이트리밋).
- 생성 실패 시 같은 프롬프트로 무한 재시도하지 않는다. 2회 실패하면 멈추고 보고한다.
- 채널 캐릭터가 정해져 있으면 Higgsfield 의 캐릭터 일관성 기능(Soul 등)을 쓴다.
  회차마다 얼굴이 바뀌면 채널 정체성이 안 생긴다.
- 결과 파일을 `{output_dir}/video/{id}.mp4` 로 내려받는다.

### 4. 사람 검수 게이트

업로드 전에 아래를 스스로 점검하고, 하나라도 걸리면 업로드하지 말고 보고한다.

- [ ] 화면에 뜬 글자에 오탈자가 없는가
- [ ] 실존 인물처럼 보이는 얼굴이 사실과 다른 말을 하고 있지 않은가
- [ ] 사실 주장(수치·인용)에 근거가 있는가
- [ ] 브리프의 톤과 맞는가

### 5. 업로드

```bash
python {scripts_dir}/youtube_upload.py upload \
  --file "{output_dir}/video/{id}.mp4" \
  --title "기획안의 title" \
  --description-file "{output_dir}/desc/{id}.txt" \
  --tags "태그1,태그2,태그3" \
  --privacy private \
  --synthetic
```

- `--synthetic` 은 **AI로 만든 사실적 영상이면 반드시 붙인다.** YouTube 의 합성 콘텐츠 공시 항목이다.
  애니메이션·명백한 비현실 연출만 있는 경우는 빼도 된다.
- 설명문에는 훅 요약 + CTA 링크 + 해시태그를 넣는다. `{output_dir}/desc/{id}.txt` 에 먼저 쓴다.
- 업로드가 끝나면 반환된 `studio_url` 을 사용자에게 전달한다. 사람이 거기서 확인하고 공개한다.

### 6. 기록

`{output_dir}/log.jsonl` 에 한 줄 추가한다.

```json
{"date":"2026-08-13","plan_id":"2026-08-13-01","video_id":"XXXX","model":"...","credits_note":"...","status":"uploaded_private"}
```

## 하지 말 것

- 공개 상태로 자동 업로드하지 않는다.
- `daily_video_cap` 을 넘겨 생성하지 않는다.
- 하나의 대본을 단어만 바꿔 여러 편으로 복제하지 않는다.
  YouTube 는 반복·양산 콘텐츠를 수익화 대상에서 제외한다. 편수보다 편당 완성도가 중요하다.
- 실존 인물의 얼굴·목소리를 동의 없이 재현하지 않는다.
