# 영상 다운로더 v2.0

`HTTP Error 403: Forbidden` 을 자동으로 우회하는 유튜브 다운로더입니다.

## 쓰는 법

### 이미 v1 을 쓰고 있다면 — `설치.bat`

`C:\Users\USER\영상다운로더` 에 깔려 있는 v1 을 v2 로 갈아끼웁니다.
**바탕화면 바로가기, 아이콘, 이름 다 그대로** 쓰면서 알맹이만 바뀝니다.

`설치.bat` 더블클릭 → `Y` 입력. 하는 일은 이렇습니다.

1. 기존 `app.py` 를 `app.py.v1백업` 으로 저장
2. v2 파일들을 그 폴더에 복사
3. **기존 `.venv` 의 yt-dlp 를 최신으로 올리고 캐시를 비움**
4. 환경 점검 결과를 보여줌

3번이 핵심입니다. 403 의 1순위 원인이 낡은 yt-dlp 라서, 파일만 바꾸고
yt-dlp 가 그대로면 소용이 없습니다.

### 새로 쓴다면 — `실행.bat`

**`실행.bat` 더블클릭.** 끝입니다.
처음 한 번은 가상환경을 만드느라 1~2분 걸리고, 그 뒤로는 바로 뜹니다.

| 파일 | 하는 일 |
|---|---|
| `설치.bat` | **기존 v1 폴더에 덮어쓰기** (바로가기 유지) |
| `실행.bat` | 이 폴더에서 바로 실행 |
| `업데이트.bat` | yt-dlp 최신화 + 캐시 비우기 — **403 이 계속되면 이걸 실행** |
| `문제진단.bat` | 어느 클라이언트가 뚫리는지 하나씩 확인 |

파이썬이 없으면 `winget install Python.Python.3.12` 로 먼저 설치하세요.

## 눌렀는데 아무 반응이 없던 문제

바로가기가 `pythonw.exe` 로 실행되는데, 이건 **콘솔 창이 없습니다.**
그래서 프로그램이 시작 단계에서 터지면 화면에 아무것도 안 뜨고 조용히 죽습니다.

v2 의 `app.py` 는 모든 예외를 붙잡아 **창으로 띄우고 `오류기록.txt` 에도 남깁니다.**
이제 무엇이 잘못됐는지 보입니다.

## 왜 403 이 났었나

v1 이 실패한 이유는 셋 중 하나입니다.

1. **yt-dlp 가 낡음** — YouTube 가 스트림 URL 서명 방식을 수시로 바꿉니다.
   구버전은 영상 목록까지는 잘 가져오지만 **실제 파일을 받는 순간** 거부당합니다.
2. **JS 런타임이 없음** — 요즘 yt-dlp 는 YouTube 챌린지를 풀려고 Deno/Node 를 부릅니다.
   없으면 서명을 못 만들어 403 이 납니다.
3. **PO 토큰 / 쿠키가 없음** — 봇으로 판정되면 거부합니다.

v1 은 한 번 실패하면 그냥 끝났습니다. 로그에 `실패 1개` 만 찍힌 게 그것입니다.

## v2 가 고친 것

**2번과 3번은 클라이언트를 바꾸면 통째로 피해갈 수 있습니다.**
`android_vr`, `ios`, `visionos` 클라이언트는 **JS 플레이어도 쿠키도 요구하지 않기** 때문입니다.

그래서 화질이 가장 좋은 것부터 시도하고, 403 이 나면 요구조건이 적은 쪽으로 한 칸씩 내려갑니다.

| 순서 | 클라이언트 | 특징 |
|---|---|---|
| 1 | 기본 | 화질 최상 |
| 2 | `tv` | 화질 좋음 |
| 3 | `android_vr` | **JS·쿠키 불필요 — 403 우회 주력** |
| 4 | `ios` | JS·쿠키 불필요 |
| 5 | `android` | JS·쿠키 불필요 |
| 6 | `visionos` | JS·쿠키 불필요 |
| 7 | `tv_simply` | 쿠키 불필요 |
| 8 | `mweb` | 모바일 웹 |
| 9 | `web_safari` | 쿠키가 있을 때 |

그 외에 이런 것들이 들어갔습니다.

- **시작할 때 yt-dlp 를 자동으로 최신화합니다** (import 전에 하므로 실제로 적용됩니다)
- **전부 막히면 자동 고치기를 제안하고, 한 번 눌러주면 알아서 복구합니다**
- 403 이 처음 나면 **낡은 서명 캐시를 한 번 비웁니다**
- 성공한 클라이언트를 기억해서 **다음 영상부터는 그걸 먼저** 씁니다 (여러 개 받을 때 빨라짐)
- 비공개·삭제·지역제한처럼 **재시도가 무의미한 경우는 즉시 중단**합니다
- yt-dlp 원본 오류 대신 **한국어 설명**을 보여줍니다
- 시작할 때 yt-dlp 버전·ffmpeg·JS 런타임을 **자동 점검**합니다

## 그래도 403 이 나면 — 아무것도 안 하셔도 됩니다

프로그램이 알아서 합니다.

**시작할 때마다** yt-dlp 가 최신인지 확인하고, 낡았으면 자동으로 올립니다.
(6시간에 한 번만 확인하므로 평소 시작은 빠릅니다.)

**전부 403 으로 막히면** "지금 자동으로 고칠까요?" 하고 물어봅니다.
`예` 만 누르면 yt-dlp 최신화 → 캐시 정리 → 재시작까지 알아서 합니다.

언제든 **`🔧 자동 고치기`** 버튼을 직접 눌러도 같습니다.

> **왜 재시작하나** — 이미 메모리에 올라온 yt-dlp 는 pip 로 올려도
> 현재 프로세스에서는 예전 코드가 그대로 돕니다. 그래서 다시 시작해야
> 새 버전이 실제로 쓰입니다. `app.py` 가 yt_dlp 를 부르기 **전에**
> 업데이트를 끝내는 것도 같은 이유입니다.

그래도 안 되면 `문제진단.bat` 을 돌려서 나온 출력을 알려주세요.
9개 클라이언트 중 어디서 막히는지 한 줄씩 나옵니다.

## 쿠키가 필요한 경우

연령제한·멤버십 전용 영상은 쿠키가 있어야 받아집니다. 설정의 `브라우저 쿠키` 에서 고르세요.

> **Chrome 은 잘 안 됩니다.** Chrome 127 부터 App-Bound Encryption 이 걸려서
> 외부 프로그램이 쿠키를 못 읽습니다 ([yt-dlp #10927](https://github.com/yt-dlp/yt-dlp/issues/10927)).
> Edge 도 같은 Chromium 이라 마찬가지입니다.
>
> **Firefox 를 쓰시면 그냥 됩니다.** 아니면 `Get cookies.txt LOCALLY` 확장으로
> 쿠키를 파일로 내보낸 뒤 `쿠키 파일 직접 지정` 을 고르세요.

쿠키 파일은 **본인 구글 계정 로그인 세션 그 자체**입니다. 공유하거나 저장소에 올리지 마세요.

## 명령줄로 쓰기

```bat
.venv\Scripts\python.exe ytdl.py "https://youtu.be/..."
.venv\Scripts\python.exe ytdl.py --check "https://youtu.be/..."   :: 클라이언트별 진단
.venv\Scripts\python.exe ytdl.py -q audio "https://youtu.be/..."  :: MP3 로
```

## 파일 구조

```
youtube-downloader/
├── 설치.bat                  기존 v1 폴더에 덮어쓰기
├── 실행.bat                  실행
├── 업데이트.bat              yt-dlp 최신화
├── 문제진단.bat              진단
├── app.py                    바로가기 진입점 (오류를 창으로 보여줌)
├── youtube_downloader.py     GUI
├── ytdl.py                   명령줄 + 진단
├── ytdl_core.py              다운로드 엔진 (403 우회 로직)
└── requirements.txt
```
